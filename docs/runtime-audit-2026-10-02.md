# 运行与权限审计（2026-10-02）

范围：基于 Frameflow 0.2.2 的源码工作树，审计启动、单实例、普通用户权限、任务退出、媒体子进程和文件保护。以下记录修复阶段的验证证据；修复纳入 0.2.3，发布构建另见 [Windows 发布验收](windows-release-verification.md)。未覆盖安装用户的正式软件。

## 发现与修复

| 项目 | 原有情况与影响 | 本次处理 |
| --- | --- | --- |
| 单实例 | 没有实例互斥；重复启动可同时修改偏好并运行任务 | 增加系统持有的文件锁；Windows 按用户和登录会话隔离，用本地事件唤回窗口；macOS 使用用户文件锁及本地 Unix 通知 |
| 再次打开媒体 | 引入单实例后若仅激活窗口，会丢失副实例参数；引擎检测中也可能丢失导入请求 | 副实例把绝对路径写入用户目录的限长请求文件，主窗口导入后清理；支持中文、空格和相对启动路径；引擎未就绪时保留请求 |
| 安装权限 | 应用已是 `asInvoker`，安装器已是 `PrivilegesRequired=lowest`，但默认 `C:\Programs\Frameflow` 不能保证普通用户可写 | 新安装默认 `%LOCALAPPDATA%\Programs\Frameflow`，保留原 AppId 和已有安装路径；应用不自动提权 |
| 升级权限 | 启动安装器成功不代表旧安装目录可更新；可能先退出应用才发现权限问题 | 启动安装器前检查安装根目录及 `tools` 可写性；失败时保留应用、已验证安装包，显示路径和解决方式；区分更新占用与权限不足 |
| 退出保护 | 关闭会直接取消媒体任务；引擎安装与软件下载线程可能被进程退出打断 | 运行任务时先确认，取消后等待清理；更新期间可等待完成后退出；软件安装器已接手时允许正常退出 |
| 媒体解析 | FFprobe 没有执行期限和输出大小上限，异常媒体/引擎可能一直挂起或持续占用内存 | 30 秒期限，标准输出 16 MiB、错误输出 256 KiB 上限；超限终止并回收直接子进程 |
| 子进程及日志 | `Child` 默认丢弃不终止进程；日志一整行先分配后截断，超长行可能占用大量内存 | FFmpeg、FFprobe、GPU 探测增加 RAII 子进程回收；媒体线程 panic 转为失败结果；单行最多保留 8000 字节 |
| 启动与导出错误 | GUI 构建启动失败不易发现；输出权限错误不够直观 | 窗口/实例初始化失败使用原生对话框；导出权限错误显示目录并提示选择用户可写位置 |

已存在并保留的保护：FFmpeg 参数经 `Command` 直接传递，子进程使用 `CREATE_NO_WINDOW`；输出写入独立暂存目录，成功后发布，重名不覆盖；取消清理当前任务的临时文件；引擎更新和软件下载写入用户目录；下载具有哈希与格式校验。

## 验证结果

- Windows GNU：`cargo test --locked`，137 通过、0 失败、5 忽略。忽略项为 3 个显式联网测试及 2 个由其他测试启动的子进程夹具。真实 FFmpeg / FFprobe 9.0.2 已加入本轮 PATH，媒体处理回归实际执行。
- `cargo fmt --all -- --check`、`cargo clippy --locked --all-targets -- -D warnings`、`cargo build --locked` 和 `git diff --check` 通过。
- 新测试覆盖独占实例、重复激活、中文路径只转交一次、实例进程被强制结束后可重新获取锁、引擎检测期间导入、退出确认、媒体超时/输出超量、panic 子进程回收和非目标文件保留。
- Inno Setup 6 成功编译生产配置，使用小型测试载荷，仅编译，未执行安装器。打包 PowerShell 脚本语法检查通过。
- Windows ACL 真实拒绝写入及拒绝全部访问：分别验证安装根目录和 `tools`，4 个场景均在启动更新前拒绝继续；恢复权限后通过，无检查文件残留，原测试文件保留。
- 从编译后的 EXE 读取 `RT_MANIFEST/1`，与 `scripts/windows.manifest` 完全一致，包括 `asInvoker`、`uiAccess=false`、`PerMonitorV2` 和 `longPathAware=true`。读取实际运行令牌确认 `TokenElevation=0`、Limited、Medium Integrity，未提权。
- 原生窗口实测：启动主实例并最小化，再从另一进程传入相对路径 `中文 空格 sample.mp4`；副实例退出码 0，仅保留原 PID，原窗口恢复，素材正常导入。
- 使用临时 10 分钟媒体启动转码，关闭按钮显示确认；确认取消后，应用与 FFmpeg 都结束，暂存目录及未完成输出均已清理，源素材保留。
- 测试前备份原偏好，测试结束恢复；恢复前后 SHA-256 一致。未修改正式安装或用户媒体。

本轮验证的是 debug 构建，SHA-256：`c6a9740ac514014e14d8c7790feb27d322f4e62d2fee9b4fcce4f7a7a12d37cc`。构建目录采用不含中文的临时路径，避免当前 MinGW 对中文链接路径的兼容问题。

## 验证边界

- macOS 实现已加入源码，本轮没有 macOS 编译或实机运行；Unix 本地 socket 路径仍受平台路径长度上限限制。
- 单实例只覆盖包含本次修复的构建；已发布旧版不参与该锁。Windows 不同登录会话各有一个实例。
- 实例锁已验证可在强制结束后释放；整个宿主被强杀、断电时的所有子孙进程和媒体暂存目录回收未作保证。正常关闭、取消和 Rust panic 展开的直接子进程回收已验证。
- 权限预检反映检查时的目录权限，不保证安装期间权限、文件占用或磁盘空间不会改变；未执行正式安装、覆盖升级、签名或发布。
- 本轮是常见桌面运行问题审计，不代表完整安全审计或全部硬件/系统组合的兼容性认证。

Windows 通知的会话范围遵循 [Microsoft 内核对象命名空间文档](https://learn.microsoft.com/en-us/windows/win32/termserv/kernel-object-namespaces)。
